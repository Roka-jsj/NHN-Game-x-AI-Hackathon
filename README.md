## 어떤 게임인가

**3레인 러너 + 계단 리듬 하이브리드.** 뒤에서 붉은 물이 차오르며 쫓아온다.

```
좌 / 우  → 레인 이동 (계단 구간에서는 한 칸 오르기)
위       → 점프    (낮은 벽을 넘는다)
아래     → 슬라이드 (높은 빔 밑을 지난다)
```

스와이프는 **릴리스가 아니라 24px을 넘는 순간** 발동한다. 릴리스까지 기다리면
반사 게임에서 치명적이다. 화살표·WASD·스페이스·1·2·3 키보드도 받는다.

**동사는 좌/우 하나뿐이다.** 러너에서는 레인 이동, 계단에서는 한 칸 오르기.
하이브리드의 최대 위험은 조작 문법이 둘이 되는 것인데, 같은 동사를 두 모드가
공유하게 해서 없앴다.

### 장애물은 형태로 구분된다

색으로 때우지 않았다. **실루엣만으로** 무엇인지 알 수 있어야 한다.

| | 생김새 | 넘는 법 |
|---|---|---|
| 낮은 벽 | 넓고 낮다 | 점프 |
| 높은 빔 | 넓고 얇고 떠 있다 | 슬라이드 |
| 기둥 | 좁고 높다 | **레인 이동밖에 없다** |

코인은 레인 위에 놓인다. 대개 **위험한 레인에 더 많다.**
핵심 긴장은 여기다 — 코인과 안전은 서로 다른 레인에 있고, 욕심이 곧 위험이다.

### 물이 쫓아온다

| 무피격 연속 회피 | 물 |
|---|---|
| 0~2 | 정상 속도로 따라온다 |
| **3 이상** | **멈춘다** |
| **6 이상** | **밀린다** |

너무 앞서가면 물이 1.25배속으로 붙는다. 여전히 일정 속도라 예측할 수 있고
순간이동은 없다. 거리가 쌓일수록 추격 거리가 620 → 340으로 좁혀진다.

### 계단 스프린트 — 회복의 유일한 기회

일정 거리마다 트랙이 계단으로 바뀐다. 약 6초. 장애물이 사라지고 계단만 남는다 —
규칙이 바뀐 것을 눈으로 안다. 좌/우를 **정확한 순서로** 눌러야 한 칸씩 오르고,
틀리면 비틀거리며 멈춘다. 오른 만큼 물이 뒤로 밀린다.

**첫 계단은 20초 뒤에 온다.** 첫 20초는 러너 문법만 가르친다.

### 특성 드래프트 — 디렉터의 전시장

계단 직후 게임이 멈추고 **특성 3개 중 1개**를 고른다. 12개 풀, 세 계열.

| 공격 | 방어 | 조작 |
|---|---|---|
| 도박사 — 점수 ×2, 물 +25% | 저체온 — 물 상승 −20% | 관성 — 레인 이동 즉시 |
| 가속 — 속도 +15% | 방패 — 충돌 1회 무효 | 활공 — 점프 체공 +40% |
| 수집가 — 코인 점수 ×2 | 시야 — 장애물이 더 멀리 보인다 | 정밀 — 회피 판정 폭 +50% |
| 연쇄 — 콤보 배수 +50% | 회복 — 계단 성공 시 물 추가 후퇴 | 제동 — 슬라이드 지속 +50% |

**어떤 3개를 제시할지가 곧 디렉터의 판단이다.** 겁쟁이에게는 공격 계열을,
도박꾼에게는 방어 계열을 밀어 넣는다. 선택 화면에 **"디렉터가 이 셋을 고른 이유"**
가 한 줄로 뜬다. 문장보다 강한 증거다.

판 사이 메타 진행은 **없다.** 순수 점수 경쟁이다.

### AI 디렉터

게임이 플레이어를 읽고 **반대편으로 판을 다시 짠다.** 난이도를 올리는 게 아니다.

| 프로파일 | 판정 | 디렉터의 대응 |
|---|---|---|
| SAFE (겁쟁이) | 중앙 레인 체류 높고 욕심 낮음 | 중앙에 장애물 집중, 코인은 바깥에, 물 +18% |
| RECKLESS (도박꾼) | 욕심 높고 아슬아슬 많음 | 코인 옆에 함정, 안전 루트에 보상, 방어 특성 제시 |
| PRECISE (장인) | 반응 이르고 거의 안 스침 | 밀도 +35%, 예고 −25%, 물 +25% |
| ERRATIC (초심자) | 반응 편차 크거나 자주 피격 | 밀도 −35%, 예고 +40%, 물 −20% |
| BALANCED (균형) | 그 외 | 3구간 압박 → 1구간 완화 교대 |

판정은 **결정론적이다.** `Math.random()` 을 쓰지 않는다 — 재현할 수 없으면 증거가
못 된다. 구간 경계에서만 갱신하고, ±0.05 히스테리시스에 더해 **판정을 바꾼 뒤
구간 3개는 유지한다.** 레버가 세계를 바꾸면 지표도 따라 바뀌기 때문에, 정책이
효과를 낼 시간을 주고 나서 다시 판정하지 않으면 자기 정책의 효과에 반응해 진동한다.

지표 임계값은 문서에서 받은 값이 아니라 **관측 분포에서 골랐다.**
성향별 봇 다섯을 각각 3분 돌려 판정 시점의 지표 벡터 192개를 모아 정했다.
그 과정에서 지표 셋이 사람이 아니라 다른 것(트랙 밀도 · 경과 시간 · 디렉터 자신의
코인 배치)을 재고 있던 것을 찾아 고쳤다. 전부 `docs/ai-log.md` 에 기록돼 있다.

**우상단 `AI` 버튼**을 누르면 디렉터 뷰가 열린다.
현재 프로파일, 판정 근거가 된 지표의 실시간 값, 다음 구간에 적용된 레버,
판정이 바뀐 이유, 청크 라이브러리 크기가 뜬다.
디버그 오버레이가 아니라 **제품 기능**이다 — 제출 영상에 이 화면이 들어간다.

## ⚠️ D-3 전에 반드시 할 일

**`data/*.json` 은 현재 오프라인 자리표시자다.**

```json
{ "generator": "offline-placeholder", ... }
```

파이프라인·스키마·폴백을 오늘 실제로 통과시키기 위해 만든 것이고,
**LLM이 만든 것이 아니다.** 이대로 제출하면 "LLM이 만든 350청크"는 사실이 아니게 된다.

```sh
export OPENAI_API_KEY=...          # .env 는 .gitignore 에 있다. 코드에 절대 넣지 않는다
node tools/bake.js                 # 실전 베이크 (모델은 OPENAI_MODEL 로 지정, 기본 gpt-4.1)
node tools/verify-chunks.js        # 사람이 검수. generator 필드가 제일 먼저 뜬다
```

`verify-chunks.js` 는 자리표시자를 감지하면 화면 가득 경고를 띄운다.

### 게이트 #2 에 대해 지금까지 알아낸 것

3분 10800프레임 중 23프레임이 16.7ms를 넘었다. 대조군으로 좁힌 결과:

| 조건 | 평균 | 16.7ms 초과 | 최대 |
|---|---|---|---|
| 전체 | 0.408ms | 23회 | 191.7ms |
| 루프 정지 (클록만) | 0.001ms | **0회** | 7.1ms |
| `--off=렌더` | 0.005ms | **0회** | 1.2ms |
| 픽셀 1/4 | 0.156ms | 23회 | **55.4ms** |

전부 `renderer.draw` 안이고, 픽셀을 1/4로 줄이면 크기가 1/4이 되지만
**발생 프레임 번호는 완전히 동일하다.** JS 로직이 아니라 래스터 비용이라는 뜻이다.
헤드리스 크로미움은 소프트웨어 래스터라이저를 쓰므로 **GPU 합성이 도는 실기기에서
같은 일이 일어나는지는 이 하네스로 알 수 없다.** 사람이 Performance 탭으로 재야 한다.
DPR 상한 2 는 이미 걸려 있고, 비용이 면적에 비례하므로 그게 곧 상한이다.
