# 자동 개선 루프 기록

`/loop` 동적 모드. 매 회차 `tools/evaluate.mjs` 를 돌려 숫자를 받고,
**가장 나쁜 항목 하나만** 고치고, 다시 재서 실제로 올랐는지 확인한다.
올랐는지 확인하지 않은 수정은 수정이 아니라 추측이다.

한 회차에 한 가지만 바꾼다 — 여러 개를 동시에 바꾸면 무엇이 효과가 있었는지 알 수 없다.

## 1회차 — 물이 밀리는 쪽을 먼저 삼키게

**고른 항목**: 무승부 2건 (우선순위 c). `spam`·`giant` 가 225초에 양쪽 기지 0으로 끝났다.
물이 양쪽을 똑같이 깎아 두 기지가 같은 프레임에 무너졌다.

**바꾼 것** (`src/game.js`, 한 곳): 물의 기지 피해를 전선 위치로 나눈다.
전선 0.5면 양쪽 같고, 0.8(내가 밀고 있음)이면 적이 1.6배·내가 0.4배를 받는다.
`물은 밀리는 쪽을 먼저 삼킨다.`

**전후**

| 지표 | 전 | 후 | |
|---|---|---|---|
| 무승부 | 2 | **0** | ✅ 목표 달성 |
| 끝나지 않은 판 | 0 | 0 | — |
| 평균 판 길이 | 172초 | 169초 | — |
| 디렉터 구성 분화 | 5 | 5 | — |
| 콘솔 | 0 | 0 | — |
| 결말 종류(구 지표) | 3 | 2 | ⚠ 아래 참조 |

**판정: 채택.** 다만 되돌릴 뻔했다.

구 지표 "서로 다른 결말"이 3→2로 내려가 규칙상 되돌릴 대상이었다.
실제 결말을 열어 보니 이랬다.

```
spam   승리 217초  내기지 155   giant  승리 222초  내기지  51
turtle 패배 154초  내기지   0   econ   승리  82초  내기지 618
```

무승부가 사라지면서 승/승/패/승이 됐을 뿐이고, **수비형은 제대로 지고
경제형은 82초에 이긴다.** 217초 승리와 82초 승리는 같은 결말이지만 전혀 다른 판이다.

즉 후퇴한 것은 게임이 아니라 **내 지표였다.** 무승부가 병증이었고 승패는 정상 결말이다.
코드를 되돌리는 대신 지표를 고쳤다 — 결말과 판 길이(60초 버킷)를 함께 센다.
새 지표로는 3종이다.

**남은 과제**: 첫 30초에 기지피해·시대진화·드래프트가 하나도 안 나온다 (우선순위 f).
다음 회차 대상이다.

## 회차 — 색을 붙이고, 문서를 되찾고, 「선택이 없다」를 찾았다

### 1. 아트 통합 — 팔레트를 그리는 쪽에 붙였다

`config.js` 에 늘려 둔 팔레트를 `render.js` 가 실제로 쓰게 했다.
유닛 6종 종류별 색 · 위협색 전용화 · 해일의 물 · 시대별 배경 색조 · 재무장 표시.

**칠할 때 램프(알파)를 안 쓴 이유**가 이 커밋의 핵심 판단이다. 알파를 쓰면
유닛이 겹치는 순간 아래층이 비쳐 밝아져서 **뭉칠수록 색이 사라진다** —
색이 제일 필요한 자리(난전)에서 정확히 무너진다. 미리 섞은 불투명색을 쓴다.

격리 트리에서 평가기 전 구간 재측정: **시뮬 수치가 한 자리도 안 바뀌었다.**
프레임 초과는 58 → **50** (예산 56). 이득의 정체는 배경도 유닛도 아니고
**결과 카드가 바뀌지도 않으면서 매 프레임 문장 20개를 다시 그리던 것**이었다.
아트 담당이 성능 원인을 여섯 번 틀리게 짚은 끝에 찾았다.

`총진군` 예고는 「판정 불가」로 남아 있었는데, 캡처 루프가 스킬 3개까지만
돌고 있던 것이었다. 코드에는 분기가 있었다. 네 번째를 붙여 찍어 확인했다 —
경고 띠 + 적 유닛 발밑 고리. **코드를 읽고 됐다고 하지 않고 찍어서 봤다.**

### 2. README 가 없어진 게임을 설명하고 있었다

두 번 장르를 바꾸는 동안 README 는 3레인 러너에 멈춰 있었다. 레인 이동,
계단 스프린트, 특성 12종, 540×960 세로 — 지금 저장소에 하나도 없다.
**심사자가 제일 먼저 읽는 문서가 제일 오래된 문서였다.**

지금 게임으로 다시 썼고, 검증 절을 「게이트 통과표」에서 **「넘으면 안 되는
경계」**로 바꿨다. 이 게임에서 중요한 건 통과가 아니라 경계다.

### 3. 이번 회차의 진짜 발견 — 선택이 존재하지 않는다

「도배가 벌을 안 받는다」를 경제에서 풀어 보려고 잰 것이 다른 곳에 닿았다.

먼저 세운 가설은 **틀렸다.** 「금이 남아돈다」는 옛 진단은 지금 트리에서
성립하지 않는다 — 프레임의 72~97%가 금 부족이고 상한에 붙는 프레임은 0%다.
아무도 부자가 아니다.

계기를 두 번 틀린 뒤에 얻은 값이다.

1. `g.uN` 을 썼는데 그런 필드가 없다(`C.UNIT_MAX` 다). 적 순회가 통째로 안 돌아
   상성 봇이 조용히 **검사 도배 봇**이 돼 있었다. 평가기가 예전에 빠졌던 함정과
   똑같은 것에 다시 빠진 것이다
2. 프레임마다 재면서 프레임마다 사는 봇으로 「상성 살 수 있음」을 쟀더니 3%가
   나왔다. **봇이 제 계기를 비운 것이다.** 재는 지점을 「구매가 실제로 일어난
   순간」으로 옮겨서 고쳤다

고친 계기가 말한 것:

```
정책      전투  구매수   선택폭   폭=1비율   상성살수있었음
상성우선       1     51     1.53       84%            0%
상성우선       3     56     1.43       88%            0%
상성우선       5     49     1.55       80%            0%
싼것부터       1     49     1.61       80%            0%
싼것부터       3     70     1.29       90%            0%
싼것부터       5     45     1.51       82%            2%
```

**구매의 80~90%에서 살 수 있는 유닛이 정확히 한 종뿐이다.** 플레이어는 고르는
게 아니라 줄을 선다. 그리고 구매 순간 최적 상성 유닛을 살 수 있는 경우가 **0%**다 —
시작 화면이 이 게임의 핵심이라고 가르치는 상성 삼각형이, 결정하는 그 순간에
구조적으로 손에 안 닿는다.

전투 5에서 상성일치가 49%·73%로 튀는 건 우연이다. 그때 **가장 싼 유닛이 마침
상성이었을 뿐**이고, 고른 게 아니라 걸린 것이다.

이것이 `config.js:134-147` 이 길게 기록한 「상성−도배 격차 ≥40%p」 실패의 진짜
이유다. 값표를 여섯 가지 방식으로 매만지고 전부 기각했는데, 애초에 **플레이어가
못 하는 선택에는 값을 매길 수 없다.** 값의 문제가 아니라 **접근의 문제**였다.

그리고 이건 사용자의 누적 불만과 같은 뿌리다 — 「난이도가 쉽고 단순하게
풀린다」「재미없다」. 누를 게 하나뿐이면 당연히 단순하다.

**다음 회차 대상.** 목표는 지갑을 키우는 게 아니라 선택폭을 넓히는 것이다.
은행이 아니라 손패 — 「지금 2~3종 중에 고른다」가 되어야 하고
「10기를 모았다 한 번에 푼다」가 되면 안 된다. 후자는 이미 한 번 기각된 안이다.

## 정정 — 바로 위 「선택이 존재하지 않는다」는 **틀렸다**

전문가를 붙여 놓고 「내 진단부터 의심하라」고 시켰더니 진단이 무너졌다.
위 절의 표는 **계기 오류 세 건 위에 서 있었다.**

**(a) 상성 가용성을 결제 *뒤에* 쟀다.** `choice.mjs` 에서 `afford(g, bc)` 가
`g.input(k)` 다음 줄에 있다. 금이 빠지고 쿨다운이 선 지갑으로 "살 수 있었나"를
묻는 것이다. 그래서 **상성만 사는 봇조차 0%로 나온다**(참값은 정의상 100%).
한 줄 올리면 상성일치 8/20/49% 와 **정확히 같아진다.**
「상성이 구조적으로 손에 안 닿는다」는 **없는 현상이었다.** 대기 시간은 0.1~0.5초다.

**(b) 선택폭 1 은 게임의 성질이 아니라 봇의 조급함이다.** 프레임마다 사는 봇은
정의상 폭 1 을 본다. 같은 트리에서 정책만 바꾸면:

```
급한상성(내 봇)  폭 1.57 / 1.34 / 1.56
참을성상성       폭 1.60 / 1.92 / 2.84
사람 1.2초       폭 4.72 / 2.83 / 5.38   ← 사람 속도에서는 이미 충족돼 있다
```

**(c) 그리고 셋 중 제일 큰 것 — 디렉터가 장님이었다.** `Game` 과 `Director` 를
직접 만들면 배선이 안 된다. `game.onEvent` 와 `director.step()` 은 **`main.js:28`
에만** 있다. `econ.mjs`·`choice.mjs`·`wipe.mjs` 전부 그것 없이 돌았다.
`focus=0.00`, 적 표 고정. 배선하면 궁수 도배에 기병 69%로 답한다.
**저 표의 모든 숫자는 AI 가 꺼진 게임의 숫자다.**

이 절을 지우지 않고 남긴다. 「고쳤다고 말하기 전에 계기를 의심한다」를 이
저장소가 몇 번이나 적어 놓고도 또 틀렸다는 사실이 기록으로서 값이 있다.
이번에 다른 점은 **틀린 진단을 들고도 전문가에게 「내 진단을 의심하라」고
먼저 시켰다는 것**뿐이다. 그게 없었으면 없는 병에 약을 지었을 것이다.

## 그래서 진짜 병은 무엇이었나 — 「실수」의 정의

처벌의 세기 `focus` 는 플레이어 구성의 정규화 허핀달이라 **왜** 몰렸는지를 안 본다.

```
집중도   상성 봇 0.40   도배 봇 1.00   순환 봇 0.02
```

상성 봇은 제대로 읽어서 몰린 것인데 도배와 같은 종류의 벌을 받는다.
그리고 상성 봇은 실제로 이기고 있었다 — 제 공격의 31.1%가 상성 우위, 적은
13.7%(피해 1.21배). 그런데 집중도 0.40 이 적 수입을 그만큼 올려 그 이득을
정확히 되가져간다. **두 항이 서로를 지운다.** 그것이 격차 0 의 정체다.

처벌을 둘로 갈랐다 — 구성 대응은 `focus` 그대로(읽히면 답이 오는 것은 정당하다),
경제 처벌만 `focus × (1 − edge)`. 면제는 지수평균이고 0 에서 시작한다.
순간값으로 걸었더니 격차가 **더 나빠졌다**(+2 → −8%p) — 적 구성은 반응이라
초반 20~30초는 안 바뀌어 있고 그 구간에 도배 봇이 면제를 다 챙긴다.

**결과: 게이트 10개 전부 ○.** 실패하던 둘이 뒤집혔다.

| | 전 | 후 |
|---|---|---|
| 상성−도배 승률 격차 | 20%p ✖ | **60%p** ○ |
| 상성−도배 기지비율 | 0.416 | **0.886** |
| 첫 전투 길이 | 64.9초 ✖ | **54.6초** ○ |
| 경계(원정·idle·도배·삼각형·콘솔·프레임) | — | **전부 유지** |

독립 하네스(봇당 120판)로도 같은 방향이다: 상성 46 → 56% · 격차 +2 → +13%p.
결정론 15/15 비트 일치. `FOCUS_EDGE=0` 이면 예전 표와 완전히 동일하다.

**남은 것, 정직하게.**
1. **기병 도배가 진짜 최강 도배(63%)인데 평가기가 안 본다** — 도배 집합이 검·궁뿐이다.
   여섯 종 전부로 재면 정직한 격차는 −17%p → −5%p. 12%p 좁혔지만 **여전히 음수다.**
   다음 회차 1순위다.
2. **첫 전투 길이 ○ 는 페이싱 개선이 아니다.** s0 「결말난 판 전체」는 64.9초로
   그대로고 움직인 건 이긴 판 중앙값뿐이다. 실질 미해결.
3. 거인·투석기는 상성 그래프에서 공격자로 안 나온다(out-degree 0). 「상성을
   읽는다」가 구조적으로 4종 중의 선택이다.
4. 디렉터 구성 분화 5 → 4. 실제 구성은 오히려 더 갈렸다(농성형이 투석기를 쓰기
   시작). 줄어든 건 지표가 `levers.mix` 를 0.1 로 반올림해 세는 버킷이 겹친 것이다.
