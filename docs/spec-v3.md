# 확장 계약 v3 — 원정(campaign)·사령관·온보딩

v2 는 "한 판"을 크게 만들었다. v3 는 **판 바깥**을 만든다.

여러 전문가가 **동시에** 작업한다. 서로의 파일을 열지 않고도 맞물리려면
무엇이 존재하는지가 먼저 못 박혀 있어야 한다. 이 문서가 그 계약이다.

**이 계약을 바꾸려면 통합 담당(메인)에게 말해야 한다. 혼자 바꾸면 남의 작업이 깨진다.**

---

## 0. 절대 제약 (전원 공통 — 위반 시 즉시 중단)

v2 와 같다. 하나도 완화되지 않았다.

- 순수 HTML + CSS + JS + Canvas 2D. **npm·번들러·프레임워크·빌드 단계 없음**
- **외부 에셋 0개.** 이미지·오디오·폰트 파일을 추가하지 않는다
- **팔레트 6색만.** `COL_BG COL_GRID COL_STRUCT COL_PLAYER COL_DANGER COL_BONUS`.
  대비는 색이 아니라 **알파 램프**로 번다
- **루프 안에서 객체·배열·문자열을 만들지 않는다.** 풀과 타입배열을 쓴다
- **판정에 `Math.random()` 금지.** 연출에만 허용
- `localStorage` / `sessionStorage` **0건.** ← 이것 때문에 원정은 **세션 메모리에만** 산다
- 고정 타임스텝 60Hz. 시뮬레이션 코드에 `deltaTime` 을 곱하지 않는다
- 상수는 `src/config.js` 에만. 순수 드로잉 좌표만 `render.js` 지역 상수 허용

## 2. 원정 — 판 하나가 아니라 여정이다

지금은 판이 끝나면 그냥 다시 시작한다. 이긴 것과 진 것이 아무 차이도 없다.
**원정**은 연속된 전투다. 이기면 다음 사령관과 붙고, 지면 원정이 끝난다.

```
game.stage        0-based 현재 전투 번호 (0 = 첫 전투)
game.stageMax     원정 전체 전투 수. C.CAMPAIGN_LEN
game.commander    현재 적 사령관 인덱스 (0~4). C.COMMANDER_* 를 가리킨다
game.campaignOver boolean — 원정 자체가 끝났는가 (패배했거나 전부 이겼거나)
game.nextStage()  다음 전투로 넘어간다. 이긴 직후에만 호출된다
```

**설계 원칙 — 원정은 리셋이 아니다.** 다음 전투로 넘어갈 때
**특성(traits)과 포탑 단계는 유지되고, 금·시대·병력은 초기화된다.**
그래야 뒤 전투에서 앞 전투의 선택이 살아 있고, 매 전투가 처음부터 시작한다.

**`localStorage` 가 금지이므로 원정은 새로고침하면 사라진다.** 이건 제약이지
버그가 아니다. 어디에도 "저장됨"이라고 쓰지 마라.

## 3. 적 사령관 — AI 디렉터에게 얼굴을 준다

이 프로젝트는 **AI 활용**을 심사받는다. 지금 디렉터의 판정은 디렉터 뷰를
켜야만 보인다. 그건 심사자 대부분이 안 켠다.

**사령관은 디렉터를 게임 안으로 끌어낸 것이다.** 다섯 프로파일이 곧 다섯 명이다.

| # | 프로파일 | 성격 |
|---|---|---|
| 0 | `RUSHER` | 쉬지 않고 병력을 쏟아붓는다 |
| 1 | `TURTLE` | 웅크리고 원거리로 갉는다 |
| 2 | `ECONOMIST` | 금을 모아 두었다가 한 번에 쏟는다 |
| 3 | `SWARMER` | 싼 유닛만 끝없이 뽑는다 |
| 4 | `BALANCED` | 어느 쪽으로도 치우치지 않았다 |

상수: `C.COMMANDER_NAME[5]`, `C.COMMANDER_LINE[5]`(전투 시작 대사),
`C.COMMANDER_TAUNT[5]`(플레이어를 읽었을 때 하는 말).

**중요 — 사령관은 디렉터를 대체하지 않는다.** 사령관은 그 전투의 **기본 성격**을
정하고, 디렉터는 그 위에서 **플레이어를 읽고** 계속 조종한다. 디렉터가
플레이어 프로파일을 새로 판정하면 사령관이 `COMMANDER_TAUNT` 를 던진다 —
**"AI 가 나를 읽었다"가 화면에 문장으로 나타나는 순간**이다. 이게 이 기능의 핵심이다.

이벤트:
```
20 EV.STAGE_START   a = 전투 번호, b = 사령관 인덱스
21 EV.STAGE_CLEAR   a = 전투 번호
22 EV.TAUNT         a = 사령관 인덱스, b = 판정된 플레이어 프로파일 인덱스
23 EV.CAMPAIGN_END  a = 클리어한 전투 수, b = 1이면 완주
```

## 4. 온보딩 — 첫 30초를 고친다

측정된 사실이다. 판이 131초인데 **첫 30초에 기지 피해·포탑·물경고가 하나도 없다.**
시대 진화·드래프트·스킬은 21초에 처음 나온다. 심사자는 30초 안에 판단한다.

**첫 전투(stage 0)는 튜토리얼을 겸한다.** 요구:
- **10초 안에** 플레이어가 뭔가를 부수거나 부서지는 것을 본다
- 첫 전투는 짧아야 한다 — 목표 **40~60초**. `C.STAGE_HP_MUL[]` 로 기지 체력을 낮춘다
- 무엇을 눌러야 하는지가 **글로 설명되지 않고 화면으로 보여야 한다**

**금지:** 조작을 막는 강제 튜토리얼, 전체 화면 설명 팝업. 플레이어는 언제나
아무 버튼이나 누를 수 있어야 한다.

## 5. 전장 변주 — 매 전투가 같아 보이면 안 된다

전투마다 협곡이 달라야 한다. `C.FLOOR_DIP` 하나로 고정된 V자를 **전투별
지형 프로파일**로 바꾼다: `C.STAGE_DIP[]`, `C.STAGE_WATER_MUL[]`.

`groundAt(x)` 의 서명은 **바꾸지 마라.** 렌더·시뮬이 같이 쓴다.
안에서 현재 스테이지 값을 참조하는 것은 자유다.

## 5.5 난이도 — 지금 너무 쉽다 (전원 최우선)

사용자 지적이다: **"게임 난이도도 너무 쉽다. 흥미를 유발할 수 있어야 한다."**

측정된 근거가 이미 있다. 평가기의 8개 원형 전략 중 **5개가 이긴다.**
아무 생각 없이 싼 유닛만 눌러도 이긴다는 뜻이다. 상성 삼각형이 돌고 시대가
5개인데 **그걸 안 써도 이기면 전부 장식이다.**

### 목표 수치 (QA 감독이 이걸로 잰다)

| 항목 | 지금 | 목표 |
|---|---|---|
| 8개 원형 전략 중 승리 | 5 | **2~3** |
| 무뇌 도배(spam) 전략 승률 | 이김 | **원정 3전투 안에 패배** |
| 대조군 idle 승리 | 0 | 0 유지 |
| 상성을 쓰는 봇 vs 안 쓰는 봇 | 차이 미미 | **상성 봇이 뚜렷이 앞선다** |
| 원정 완주율(무작위 아닌 고정 봇) | — | **1/8 이하** |

### 어렵게 만드는 방법 — 순서가 중요하다

**나쁜 난이도**는 적 체력·수입을 올리는 것이다. 그러면 같은 플레이가 그냥
오래 걸릴 뿐 배우는 게 없다. **좋은 난이도는 플레이어의 실수를 처벌한다.**

우선순위:

1. **상성을 안 쓰면 진다.** `COUNTER_STRONG` 1.75 가 충분한가? 한 종류만
   도배하는 플레이가 실제로 벌을 받는지 재라. 디렉터의 상성 대응이 이미
   플레이어 구성을 읽고 카운터를 뽑는다 — **그게 아프게 느껴져야 한다**
2. **적이 스킬과 포탑을 쓴다.** 지금 적은 유닛만 뽑는다. 사령관이 해일·화살비를
   쓰고 포탑을 지으면 플레이어도 그걸 배운다
3. **원정이 갈수록 어려워진다.** `C.STAGE_DIFF[]` — 뒤 전투일수록 적 수입·
   시대 시작·사령관 공격성이 오른다. 마지막 사령관은 실제로 강해야 한다
4. **물이 다시 위협이 된다.** 페이싱 수정에서 `DROWN_DPS` 를 15→3 으로
   낮춰 교착을 풀었다. **되돌리지 마라** — 그건 병력이 전선에 못 닿게 만들어
   교착을 굳혔다. 대신 후반 스테이지에서 `STAGE_WATER_MUL` 로 수위 속도만 올려
   **시간 압박**을 준다. 익사 피해가 아니라 마감 시계다

### 금지 — 이렇게 어렵게 만들면 실패다

- 적 기지 체력을 그냥 크게 만들기 → 판만 길어진다
- 적 수입을 크게 올리기 → 초반에 손 쓸 새 없이 밀린다. 학습이 안 된다
- 무작위로 불리하게 만들기 → **`Math.random()` 은 판정에 금지다.**
  어려움은 재현 가능해야 배울 수 있다
- 첫 전투를 어렵게 하기 → 첫 전투는 **가르치는 전투**다 (§4)

**난이도는 곡선이지 상수가 아니다.** 첫 전투는 40~60초에 이기고, 마지막
전투는 지는 것이 기본값이어야 한다.

## 6. 각 전문가에게

- **원정 설계자** (`game.js`) — 2·4·5 전부. 원정이 **끝날 수 있어야** 한다.
  `tools/evaluate.mjs` 로 원정 완주 시간과 스테이지별 승률을 재라.
  **첫 전투 40~60초**를 못 맞추면 수치가 아니라 구조를 의심해라
- **아트 디렉터** (`render.js`) — 사령관 초상(6색·코드로만) · 대사 말풍선 ·
  원정 진행 표시 · 결과 화면 · **전투 가독성**(지금 유닛이 흰 덩어리로 뭉쳐
  뭐가 뭔지 안 보인다. 진영 구분이 최우선이다) · **폰 세로 대응**
- **오디오 감독** (`audio.js`) — 사령관 5인 테마(음색·화성으로 구분) ·
  전투 시작/클리어/원정 종료 · 도발 대사 순간. **오디오 파일 0개**
- **밸런스·AI 감독** (`director.js`) — 사령관을 디렉터에 연결하고,
  **도발이 실제로 플레이어 판정과 맞물리는지** 증명해라. 스테이지 난이도 곡선
- **QA 감독** (`tools/evaluate.mjs`) — 원정을 재는 항목을 만든다.
  완주율 · 스테이지별 승률 · 첫 전투 길이 · 도발 발생률 · 첫 10초에 무엇이 일어나는가
- **게임 평론가** (`docs/game-review.md`) — 업그레이드 후 다시 채점

Renderer.hitButton(lx,ly) / hitRally / hitCard / hitToggle / hitMute

## 부록 B — 이 프로젝트가 반복해서 배운 것

새로 오는 전문가는 이것부터 읽어라. 같은 실수를 네 번 했다.

1. **증상의 가장 그럴듯한 원인은 대개 틀렸다.**
   - 유닛이 전부 붉게 보임 → 물 알파를 세 번 낮췄지만 원인은 **피격 플래시**였다
   - 포탑이 놀았음 → 연사를 의심했으나 원인은 **표적 부재(사거리)**였다
   - 프레임 스파이크 → GC·배경·폰트를 의심했으나 원인은 **그리기 호출 개수**였다
   - 판이 안 끝남 → 물이 기지를 깎는 줄 알았으나 **물이 병력을 전선 전에 죽이고** 있었다
2. **측정 도구를 먼저 의심해라.** 레버 ON/OFF 가 같은 값을 낸 적이 있는데,
   원인은 봇이 내내 BALANCED 로 판정돼 레버가 중립이었기 때문이었다
3. **추론으로 상수를 고르지 마라.** 궁수 최소사거리를 30 으로 추론했으나
   실측 최적은 44 였고, 70·96 으로 올리면 **오히려 나빠졌다**
4. **되돌린 것을 보고해라.** 기지 앞마당은 기지 타격을 만들었지만 상성 삼각형을
   6/6 → 5/6 으로 깼다. 그 보고가 이 프로젝트에서 가장 값진 산출물이었다
